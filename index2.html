Quick-start template

A complete, standalone program that works unchanged with C++17 or C++20. Paste it into quickstart.cpp, compile, run — if this works, everything in this guide will.

// quickstart.cpp - a minimal but complete C++17/20 program
#include <iostream>
#include <string>
#include <vector>

// a small function, so the template shows the full shape of a program
int sum(const std::vector<int>& numbers) {
    int total = 0;
    for (int n : numbers) {   // range-for: visits every element
        total += n;
    }
    return total;
}

int main() {
    std::cout << "this template compiles under C++17 and C++20\n";

    std::string name;
    std::cout << "your name: ";
    std::getline(std::cin, name);       // getline: reads spaces too

    std::vector<int> scores = {90, 75, 100};
    scores.push_back(60);               // vector grows on its own

    std::cout << "hi " << name << "!\n";
    std::cout << "scores total: " << sum(scores) << '\n';
    return 0;
}

Part 1 — Core concepts

Nine short sections. The first four are mostly review of things you have already written; the last five are the C++ your practice file hasn't reached yet.

1.1 Variables & types

REVIEW + auto
The five types your practice file already uses
TypeHoldsExample
intwhole numbersint age = 21;

// the classic trap you already fixed once in your own file:
std::cout << 8 / 10 << '\n';     // 0    (int / int throws away decimals)
std::cout << 8 / 10.0 << '\n';   // 0.8  (making one side a double is enough)
auto is new to you: the compiler figures out the type from the value. It only works when you initialize the variable immediately — auto x; alone is an error, because the compiler has nothing to read the type from.

1.2 Control flow

REVIEW + range-for 
if (score >= 90)       { std::cout << "A"; }
else if (score >= 80)  { std::cout << "B"; }
else                   { std::cout << "keep going"; }

switch (menuChoice) {
    case 1: deposit();  break;    // no break = falls into the next case
    case 2: withdraw(); break;    // (a bug you already met in your calculator)
    default: std::cout << "invalid"; break;
}

int biggest = (a > b) ? a : b;   // ternary: condition ? then : else

while (name.empty())  { /* ask again */ }
do { playRound(); } while (again == 'y');   // runs the body at least once
for (int i = 0; i < 5; i++) { /* i = 0,1,2,3,4 */ }
for (int value : numbers) { /* every element, no index needed */ }  // NEW
The only new item is the range-based for loop: for (int value : numbers) visits every element of an array, vector, or string without you managing an index — so no more off-by-one mistakes like a loop bound of temp < 4 on a 5-element array.

1.3 Functions

REVIEW + references & defaults 
int add(int a, int b);            // declaration: promises "this exists"

int add(int a, int b) {           // definition: the actual body
    return a + b;
}

void greet(std::string name = "friend") {   // default argument
    std::cout << "hi " << name << '\n';
}

void levelUp(int& hp) { hp += 10; }         // & = by reference: changes stick

int main() {
    greet();              // hi friend
    greet("khaled");      // hi khaled

    int hp = 5;
    levelUp(hp);          // hp is now 15 - the ORIGINAL changed
    std::cout << add(hp, 5);   // 20
}
  • Your banking program already used declarations — prototypes like void showBalance(double balance); above main(), definitions below it.
  • Overloading (your four bakepizza functions) means several functions share a name but take different parameters.
  • New: pass by value (the default) gives the function a copy; pass by reference (int&) gives it the original — that's why levelUp(hp) can change hp back in main.

1.4 Strings, arrays & vectors

REVIEW + vector 
int scores[5] = {90, 85, 70, 95, 60};   // C-style array: size fixed forever
scores[0] = 100;                         // index 0 is the FIRST element

std::vector<int> levels;                 // vector: starts empty, grows itself
levels.push_back(1);
levels.push_back(2);
levels.push_back(3);
std::cout << levels.size();              // 3

for (int value : levels) {               // range-for works on vectors too
    std::cout << value << ' ';
}

std::string s = "khaled";
std::cout << s.length() << s.at(0);      // 6k  (methods you already know)
  • String methods you already use: .length(), .empty(), .clear(), .append(), .at(), .insert(), .find(), .erase().
  • New: std::vector is a resizable array — push_back adds to the end, .size() tells you the length, and .at(i) checks the index is legal before reading (plain [i] doesn't).
  • Rule of thumb for your projects: use a vector unless you know the exact size at compile time.

1.5 Pointers & references

NEW 
int hp = 100;

int& alias = hp;        // reference: a second NAME for the same box
alias -= 30;            // hp is now 70

int* ptr = &hp;         // pointer: stores hp's ADDRESS
std::cout << ptr;       // something like 0x7ffee3b4c8fc
std::cout << *ptr;      // 70 - the * follows the address ("dereference")
*ptr = 50;              // writes through the address - hp is now 50

int* nothing = nullptr; // "points nowhere" - never dereference this
  • The character & has two jobs: int& declares a reference; &hp reads an address. Context decides which — confusing at first, normal later.
  • A reference must be attached to something and can never be reattached. A pointer can be moved, can point at nothing (nullptr), and can be null-checked.
  • Why you care right now: (1) pass by reference, as in 1.3; (2) getting elements "in place" instead of copies, which the walkthrough uses; (3) under the hood, arrays and vectors are built on pointers.
Rule of thumb: prefer references when you can, pointers when you must — you need a pointer mainly when "nothing" is a legal state (nullptr).

1.6 Classes & objects

NEW 
struct Task {                 // struct: groups data, everything public
    std::string text;
    bool done = false;
};

class Player {                // class: data + the functions that guard it
private:                      // outside code cannot touch these directly
    std::string name;
    int hp;
public:                       // the safe doorway everyone uses
    Player(std::string n, int startHp)     // constructor: runs on creation
        : name(n), hp(startHp) {}

    void takeDamage(int amount) {
        if (amount > 0) hp -= amount;      // the class enforces its own rules
    }
    int getHp() const { return hp; }       // const: promises not to modify
};

int main() {
    Player hero("khaled", 100);   // an OBJECT, built from the blueprint
    hero.takeDamage(30);
    std::cout << hero.getHp();    // 70
    // hero.hp = -999;            // ERROR: hp is private - protected by design
}
  • A class is a blueprint; an object is one real thing built from it. You've used objects all along — std::string and its dot-methods are exactly this.
  • private / public = encapsulation: data can only change through the class's own functions, so the class can keep its own rules (like "hp never goes negative").
  • A constructor runs automatically when the object is created, so it can never exist half-initialized.
  • struct and class are the same thing except struct members are public by default — the convention is struct for plain data, class when there are rules to enforce.

1.7 Inheritance & polymorphism

NEW 
class Account {                          // base class ("parent")
protected:                               // visible to children, hidden outside
    double balance = 0.0;
public:
    void deposit(double amount) { if (amount > 0) balance += amount; }
    virtual void printInfo() const {     // virtual: children may replace this
        std::cout << "account: " << balance << '\n';
    }
    virtual ~Account() = default;        // safe habit for a parent class
};

class SavingsAccount : public Account {  // "a savings account IS an account"
public:
    void addInterest() { balance += balance * 0.03; }
    void printInfo() const override {    // override: replaces the parent's version
        std::cout << "savings: " << balance << '\n';
    }
};

int main() {
    SavingsAccount s;
    Account& a = s;      // a parent reference to a child object
    a.printInfo();       // prints "savings: ..." - the CHILD's version runs
}
  • Inheritance (class Child : public Parent) means "is a": a SavingsAccount is an Account, so it gets deposit() for free and only adds what makes it special.
  • Polymorphism = one call, many behaviors. Because printInfo() is virtual, C++ picks the version that matches the actual object, not the type of the reference — that's why a.printInfo() prints the savings version.
  • Always write override on replacements — the compiler then checks you actually matched the parent's signature.

1.8 Templates

NEW 
// your four bakepizza() overloads, generalized into ONE function:
template <typename T>
T biggest(T a, T b) {
    return (a > b) ? a : b;
}

biggest(3, 7);                    // T = int     -> 7
biggest(2.5, 1.5);                // T = double  -> 2.5
biggest<std::string>("apple", "pear");

// templates work for classes too:
template <typename T>
class Box {
    T item;
public:
    void put(T thing) { item = thing; }
    T get() const { return item; }
};

Box<int> hp_box;               // a Box that holds ints
Box<std::string> name_box;     // a Box that holds strings
A template is a recipe, not code yet. When you call biggest(3, 7), the compiler stamps out an int version on the spot; biggest(2.5, 1.5) stamps out a double version. You write the logic once, the compiler writes the overloads.

1.9 STL basics

NEW 
#include <vector>
#include <map>
#include <algorithm>

std::vector<int> scores = {60, 90, 75, 90};
scores.push_back(100);
std::cout << scores.size();                              // 5

std::sort(scores.begin(), scores.end());                 // 60 75 90 90 100
int nines = std::count(scores.begin(), scores.end(), 90); // 2

std::map<std::string, int> wins;      // key -> value pairs, sorted by key
wins["khaled"] = 3;
wins["computer"] = 1;
if (wins.count("khaled")) std::cout << wins["khaled"];   // 3

for (const auto& entry : wins)        // entry.first = key, entry.second = value
    std::cout << entry.first << ": " << entry.second << '\n';
  • You have been using the STL all along — std::string and std::vector are part of it. "STL" just means the standard library's ready-made containers and algorithms.
  • std::sort and std::count take a range: where to start (.begin()) and where to stop (.end()). These positions are called iterators.
  • std::map is a dictionary: look up a value by a key instead of a number index — perfect for "score per player" or "price per item".

Part 3 — Worked walkthrough: the Vending Machine

A complete, easy simulation project built step by step, the way you'd actually do it: decide the data, write the helpers, wire it up, then test. Difficulty ★★☆☆☆ — doable with sections 1.1–1.4 alone. Copy the method, then apply it to the projects above.

The scenario

A vending machine sells four items. Customers insert coins, buy items, and get change. An admin can restock. On shutdown the machine reports how much money it collected.

Requirements

  1. Show all four items with price and remaining stock.
  2. Accept coins of 5, 10, 25 and 100 cents; reject anything else.
  3. Buying an item needs enough credit and stock; on success the stock drops and the difference is returned as change.
  4. Show the current credit at all times.
  5. Admin option: restock every item to 5.
  6. On quit, print the total money collected.
  7. Never crash on bad input — not even if the user types letters.
Design decision — money as whole cents. Prices are stored as int (125 means $1.25). This dodges the classic floating-point problem where 0.1 + 0.2 comes out as 0.30000000000000004. Rule: floats for measurements, integers for money and anything you count.

Step-by-step build

Step 1 — the data

Each product is one struct; the machine's shelf is a vector of them.

struct Item {
    std::string name;
    int priceCents;
    int stock;
};

std::vector<Item> items = {
    {"water", 125, 5},
    {"chips", 150, 5},
    {"candy",  90, 5},
    {"soda",  175, 5},
};
  • One row per product — {"water", 125, 5} fills name, then priceCents, then stock, in order.
  • Adding a fifth product later means adding one row here. Nothing else changes.

Step 2 — safe number input

You already wrote this pattern in your calculator: if the user types letters, cin fails and must be cleared before retrying.

int readInt(const std::string& prompt) {
    int value;
    std::cout << prompt;
    std::cin >> value;
    while (std::cin.fail()) {                     // user typed letters
        std::cin.clear();                         // undo the error flag
        std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
        std::cout << "please enter a number\n";  // throw the bad input away
        std::cout << prompt;
        std::cin >> value;
    }
    return value;
}
  • clear() resets the error; ignore(...) throws away everything the user typed up to the newline.
  • Take the address of a string (const std::string&) so the prompt isn't copied every call — pass-by-reference from §1.3 doing quiet work.
  • Needs #include <limits>. Every input in this program goes through this function — requirement 7 solved once, everywhere.

Step 3 — show the menu

void showMenu(const std::vector<Item>& items, int credit) {
    std::cout << "\n===== VENDING MACHINE =====\n";
    for (std::size_t i = 0; i < items.size(); i++) {
        std::cout << (i + 1) << ") " << items[i].name << " - "
                  << items[i].priceCents << "c ("
                  << items[i].stock << " left)\n";
    }
    std::cout << "credit: " << credit << "c\n";
    std::cout << "5) insert coin   6) restock   7) quit\n";
}
  • Menu numbers are 1–4, but vector indexes are 0–3 — so the print uses i + 1 and the buy step will use number - 1. Pick a convention once and stick to it everywhere.
  • std::size_t is the type .size() actually returns; comparing it to a plain int i makes the compiler warn.

Step 4 — insert coins

void insertCoin(int& credit) {
    std::cout << "accepted coins: 5, 10, 25, 100\n";
    int coin = readInt("coin: ");
    if (coin == 5 || coin == 10 || coin == 25 || coin == 100) {
        credit += coin;
        std::cout << "credit is now " << credit << "c\n";
    } else {
        std::cout << "the machine spits that coin back out\n";
    }
}
  • int& credit is §1.5 doing real work: the function receives the original credit from main, so the change survives after the function ends. Drop the & and this silently stops working — the function would update a copy.
  • Rejecting unknown coins is a whitelist check: valid list first, everything else bounces.

Step 5 — buy an item

void buy(std::vector<Item>& items, int number, int& credit, int& collected) {
    Item& item = items[number - 1];        // menu number -> vector index
    if (item.stock <= 0) {
        std::cout << "sold out, sorry\n";
    } else if (credit < item.priceCents) {
        std::cout << "not enough credit - insert "
                  << (item.priceCents - credit) << "c more\n";
    } else {
        item.stock--;
        int change = credit - item.priceCents;
        collected += item.priceCents;
        credit = 0;
        std::cout << "*thunk* - a " << item.name << " drops out\n";
        std::cout << "change returned: " << change << "c\n";
    }
}
  • Item& item is a reference to the actual row — item.stock-- edits the shelf, not a copy.
  • Order of checks: sold out before credit (either order works — but pick one and stay consistent so testing is predictable).
  • Money is only counted as "collected" when a purchase succeeds — a failed attempt leaves credit untouched.

Step 6 — restock

void restock(std::vector<Item>& items) {
    for (Item& item : items) item.stock = 5;
    std::cout << "all items restocked to 5\n";
}
  • Range-for with Item& (by reference!) — without the & each item would be a copy and nothing would change. The single most common range-for bug.

Step 7 — wire it together

int main() {
    std::vector<Item> items = {           // the shelf
        {"water", 125, 5},
        {"chips", 150, 5},
        {"candy",  90, 5},
        {"soda",  175, 5},
    };
    int credit = 0;                        // coins currently inside
    int collected = 0;                     // money earned (survives purchases)
    int choice = 0;

    while (choice != 7) {
        showMenu(items, credit);
        choice = readInt("> ");
        switch (choice) {
            case 1: case 2: case 3: case 4:   // items 1-4 all mean "buy that"
                buy(items, choice, credit, collected);
                break;                        // <-- you know exactly why
            case 5: insertCoin(credit); break;
            case 6: restock(items); break;
            case 7: std::cout << "bye! money collected: "
                        << collected << "c\n"; break;
            default: std::cout << "unknown option\n";
        }
    }
    return 0;
}
  • case 1: case 2: case 3: case 4: stacked on purpose — several labels sharing one body. That's the good kind of fallthrough, completely different from forgetting a break;.
  • The three state variables (items, credit, collected) live in main and get passed to whoever needs them — the menu loop is the program's memory.
