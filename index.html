📘 Core C++ study notes

Everything below is organised so you can read it start‑to‑finish. Click any topic to expand it. All code is C++17/20 compatible.

Variables, types & constants

C++ is statically typed: every variable has a fixed type known at compile time.

TypeStoresExample
intWhole numbersint age = 21;
doubleDecimal numbersdouble price = 9.99;
charSingle characterchar grade = 'A';
booltrue / falsebool ready = true;
std::stringTextstd::string name = "Ada";

const makes a value read‑only. Use it for anything that shouldn't change.

const double PI = 3.14159;
// PI = 3.14; // ❌ compile error
💡 Integer division trap: int / int throws away the decimal part. Cast one side to double: (double)a / b.
Control flow — if, switch, loops

if / else if / else

if (score >= 90)      std::cout << "A";
else if (score >= 80) std::cout << "B";
else                   std::cout << "C";

switch

Best when comparing one variable against exact values. Always add break; unless you deliberately want fallthrough.

switch (op) {
  case '+': result = a + b; break;
  case '-': result = a - b; break;
  default:  std::cout << "unknown";
}

Loops

// while — checks first
while (name.empty()) { std::getline(std::cin, name); }

// do‑while — runs at least once
do { std::cin >> num; } while (num < 0);

// for — counted
for (int i = 0; i < 5; ++i) std::cout << i << ' ';
Functions — parameters, return values, overloading

A function bundles reusable logic. void means “returns nothing”.

// returns int
int add(int a, int b) { return a + b; }

// void — just prints
void greet(std::string name) {
  std::cout << "Hello, " << name << '\n';
}

// overloaded — same name, different parameters
double add(double a, double b) { return a + b; }
📌 Pass‑by‑value vs pass‑by‑reference: int x copies the value; int& x lets the function modify the caller's original.
Arrays & strings

Arrays (fixed size)

int nums[5] = {10, 20, 30, 40, 50};
for (int i = 0; i < 5; ++i) std::cout << nums[i] << ' ';

Indices start at 0. A 5‑element array has valid indices 0–4.

std::string

std::string s = "hello";
std::cout << s.length();     // 5
s += " world";               // append
if (s.find("world") != std::string::npos) { /* found */ }
Use std::getline(std::cin, s) for full lines with spaces; std::cin >> s stops at the first space.
Pointers & references (a first look)

A pointer stores a memory address. A reference is an alias for an existing variable.

int value = 42;
int* ptr = &value;     // ptr holds the address of value
*ptr = 100;            // dereference → value is now 100

int& ref = value;      // ref is another name for value
ref = 7;               // value is now 7
🔹 Pointers can be null or reassigned; references must be initialised and can't be reseated. Use references for function parameters when you want to modify the caller's variable.
Classes, objects & inheritance

A class groups data (attributes) and behaviour (methods). An object is an instance of a class.

class Dog {
public:
  std::string name;
  int age;

  Dog(std::string n, int a) : name(n), age(a) {}  // constructor

  void bark() const { std::cout << name << " says woof!\n"; }
};

int main() {
  Dog rex("Rex", 3);
  rex.bark();
}

Inheritance

class Animal { public: void eat() { std::cout << "eating\n"; } };
class Cat : public Animal { public: void meow() { std::cout << "meow\n"; } };
Templates — generic code

Write a function or class once, use it with any type.

template <typename T>
T maxOf(T a, T b) { return (a > b) ? a : b; }

int main() {
  std::cout << maxOf(3, 7);       // int
  std::cout << maxOf(2.5, 1.8);   // double
}
STL basics — vector, map, algorithm

The Standard Template Library gives you ready‑made containers and algorithms.

#include <vector>
#include <map>
#include <algorithm>

std::vector<int> nums = {5, 2, 8, 1};
nums.push_back(10);                 // add
std::sort(nums.begin(), nums.end()); // sort

std::map<std::string, int> ages;
ages["Ada"] = 36;
ages["Bob"] = 42;

for (auto& [name, age] : ages)
  std::cout << name << " is " << age << '\n';

Project 1 · Console calculator (beginner)

Console Control flow

Objective

Build a calculator that takes two numbers and an operator, then prints the result. Handle division by zero.

Concepts needed

  • Variables, std::cin / std::cout
  • switch or if/else
  • Type casting for division

Sample skeleton

#include <iostream>

int main() {
    double a, b; char op;
    std::cout << "Enter expression (e.g. 4 + 5): ";
    std::cin >> a >> op >> b;

    switch (op) {
        case '+': std::cout << a + b; break;
        case '-': std::cout << a - b; break;
        case '*': std::cout << a * b; break;
        case '/':
            if (b == 0) std::cout << "Cannot divide by zero";
            else        std::cout << a / b;
            break;
        default: std::cout << "Unknown operator";
    }
}
Quick rubric
  • ✅ Compiles and runs without errors
  • ✅ Handles all four operations
  • ✅ Division‑by‑zero handled
  • ✅ Clear prompts and output
Project 2 · Number guessing game (beginner+)

Console Loops Random

Objective

Generate a random number 1–100. Let the user guess until correct; give “too high / too low” hints and count tries.

Concepts needed

  • do‑while loop
  • srand / rand from <cstdlib>, <ctime>
  • Conditionals

Sample skeleton

#include <iostream>
#include <cstdlib>
#include <ctime>

int main() {
    srand(time(0));
    int secret = rand() % 100 + 1;
    int guess, tries = 0;

    do {
        std::cout << "Guess (1‑100): ";
        std::cin >> guess;
        ++tries;
        if (guess > secret)      std::cout << "Too high\n";
        else if (guess < secret) std::cout << "Too low\n";
        else                     std::cout << "Correct in " << tries << " tries!\n";
    } while (guess != secret);
}
Quick rubric
  • ✅ Random number changes each run
  • ✅ Hint messages correct
  • ✅ Tries counted and displayed
  • ✅ Loop ends only on correct guess
Project 3 · Text‑based adventure (text UI)

Text UI Functions State

Objective

Create a tiny “choose your own path” story. The player picks options (1, 2, 3) and the story branches. Track health or score.

Project 5 · Bank account class (OOP design)

OOP Classes Encapsulation

Objective

Design a BankAccount class with deposit, withdraw, and getBalance. Prevent negative deposits and overdrafts. Create two accounts and simulate transactions.

Concepts needed

  • Classes, constructors, public/private
  • Member functions
  • Simple validation

Sample skeleton

class BankAccount {
private:
    double balance;
public:
    BankAccount(double initial) : balance(initial) {}
    void deposit(double amt) {
        if (amt > 0) balance += amt;
    }
    bool withdraw(double amt) {
        if (amt > 0 && amt <= balance) { balance -= amt; return true; }
        return false;
    }
    double getBalance() const { return balance; }
};
Quick rubric
  • ✅ Class with private data
  • ✅ Deposit / withdraw logic correct
  • ✅ Overdraft prevented
  • ✅ Clear test in main()
Project 6 · Inventory system with inheritance (intermediate)

OOP Inheritance Polymorphism

Objective

Create a base Item class and derived Weapon, Potion classes. Store them in a vector of pointers and print a description of each.

Concepts needed

  • Inheritance, virtual functions
  • std::vector<Item*>
  • Dynamic memory (or smart pointers)

Sample skeleton

#include <iostream>
#include <vector>
#include <memory>

class Item {
public:
    virtual void describe() const { std::cout << "Generic item\n"; }
    virtual ~Item() = default;
};
class Weapon : public Item {
    int damage;
public:
    Weapon(int d) : damage(d) {}
    void describe() const override { std::cout << "Weapon, dmg " << damage << '\n'; }
};

int main() {
    std::vector<std::unique_ptr<Item>> inventory;
    inventory.push_back(std::make_unique<Weapon>(10));
    for (auto& item : inventory) item->describe();
}
Quick rubric
  • ✅ Base + 2 derived classes
  • ✅ Virtual function overridden
  • ✅ Vector of pointers used safely
  • ✅ Polymorphic call works

🎮 Worked simulation · “Coffee shop queue”

A complete, easy simulation that ties together variables, loops, functions, and basic OOP. Follow the steps; then run the full code.

Scenario & requirements

Scenario: A small coffee shop opens for 10 minutes. Customers arrive randomly (0–2 per minute). Each customer orders a drink that takes 1–3 minutes to make. The barista serves one customer at a time. Simulate the queue and report how many customers were served and how many were left waiting.

Requirements:

  • Use a std::queue<int> to store waiting customers (each customer = drink prep time).
  • Every simulated minute: new customers arrive, barista works on one drink.
  • Track total served and remaining queue at the end.
  • Print a minute‑by‑minute log.
Step‑by‑step implementation

Step 1 — Set up the simulation loop

#include <iostream>
#include <queue>
#include <cstdlib>
#include <ctime>

int main() {
    srand(time(0));
    std::queue<int> waiting;   // each int = minutes needed for that drink
    int served = 0;
    int currentDrinkTime = 0;  // remaining time on the drink being made

Step 2 — Simulate 10 minutes

    for (int minute = 1; minute <= 10; ++minute) {
        // 1. New customers arrive (0, 1, or 2)
        int arrivals = rand() % 3;
        for (int i = 0; i < arrivals; ++i)
            waiting.push(rand() % 3 + 1);  // 1–3 minutes per drink

        // 2. Barista works
        if (currentDrinkTime == 0 && !waiting.empty()) {
            currentDrinkTime = waiting.front();
            waiting.pop();
        }
        if (currentDrinkTime > 0) {
            --currentDrinkTime;
            if (currentDrinkTime == 0) ++served;
        }

        // 3. Log
        std::cout << "Minute " << minute
                  << " | queue: " << waiting.size()
                  << " | serving time left: " << currentDrinkTime
                  << " | served: " << served << '\n';
    }

Step 3 — Final report

    std::cout << "\n--- Closing time ---\n";
    std::cout << "Total served: " << served << '\n';
    std::cout << "Still waiting: " << waiting.size() << '\n';
    return 0;
}
💡 The queue holds drink times; the barista pulls the next drink only when free. This naturally models a single‑server queue.
