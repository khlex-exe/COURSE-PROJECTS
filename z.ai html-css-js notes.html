1. HTML Foundations HTML

1.1 Page skeleton

Every file you wrote starts with the same correct skeleton. Learn it by heart:

<!DOCTYPE html>                          <!-- tells the browser: modern HTML -->
<html lang="en">
<head>                                    <!-- invisible info ABOUT the page -->
    <meta charset="UTF-8">                <!-- allows all characters/emojis -->
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>page @htmlcourse@</title>      <!-- text on the browser tab -->
    <link rel="stylesheet" href="style.css">   <!-- CSS goes in the head -->
</head>
<body>                                    <!-- everything the user SEES -->
    <script src="app.js"></script>         <!-- JS at the end of the body -->
</body>
</html>
Only <meta>, <title>, <link>, <style> and <script> belong in the <head>. In two of your files (index4.html and project2.html) a <center> tag ended up inside the head — the browser silently moves it, but it is invalid. I fixed both.

1.2 Text, headings and comments

  • <h1>–<h6>: the only difference is default font size / importance. Use one h1 per page for the main title.
  • <p> = paragraph. <hr> = horizontal line (thematic break). <br> = line break.
  • Comment shortcut in VS Code: Ctrl + / — comments are invisible in the page.
  • Whatever you write inside <body> counts even without quotes — but the browser only understands it if it is inside real tags.
  • lorem in VS Code generates filler text; lorem10 generates exactly 10 words.

1.3 Images

<img src="hold your horses.jpg" width="300" height="200" alt="this is a pic">
  • src = where the picture is. alt = text shown if the image fails / for screen readers. Always write alt.
  • width/height as HTML attributes take numbers or px values; in CSS you write width: 300px;
  • If the image shows as broken, the file name/extension is wrong — check spelling and case.

3. Positioning, Flexbox & Grid LAYOUT

3.1 position (index5.html, lec27thirdhalf.html, project.html)

ValueMeaningtop/left work?
staticdefault, normal flow❌ ignored
relativeoffset from its own normal spot; becomes the reference frame for absolute children✅
absolutepinned to the nearest positioned ancestor (or the page); removed from flow✅
fixedglued to the viewport, survives scrolling (your PROJECT.css navbar)✅
stickyscrolls normally until it reaches top:0, then sticks (your title bar + index5 div)✅ (needs a top/left value)
div{
    position: sticky;
    top: 0;            /* sticky/absolute/fixed do nothing without this */
    z-index: -1;       /* stacking order: higher = in front */
}

Your image-overlap demo (lec27thirdhalf) works because both images are position:absolute inside a position:relative parent, and z-index decides who is on top.

3.2 Flexbox (index67.html, navbars everywhere)

.container{
    display: flex;                      /* children sit on one line  */
    flex-direction: row;                /* row | row-reverse | column | column-reverse */
    justify-content: space-around;      /* main axis: flex-start | flex-end | center | space-between | space-around | space-evenly */
    align-items: center;                /* cross axis: stretch (default) | center | flex-start | flex-end */
    flex-wrap: wrap;                    /* let items wrap to a new line instead of squashing */
    gap: 20px;                          /* clean spacing, no margins needed */
}
  • justify-content = along the row; align-items = up/down. Swapped when flex-direction: column.
  • On the items themselves (lec27): order: 2 reorders visually; flex-grow: 1 lets an item stretch to fill free space; flex-shrink: 4 makes it shrink 4× faster when space runs out.
  • Your navbar recipe (used in nearly every project): display:flex; justify-content:space-between; align-items:center; padding: 15px 30px; — learn this one by heart.

9. Best-Practice Checklist HABITS

HTML

  • Every <img> gets an alt.
  • Every label for matches an input id.
  • No <center>, no border attribute — use CSS.
  • Nothing visible inside <head>.
  • Semantic tags: nav/header/main/section/footer.

CSS

  • Start every file with the *{...box-sizing:border-box} reset.
  • Prefer :root variables for your color palette.
  • transition always needs a duration.
  • camelCase in JS, kebab-case in CSS: fontSize vs font-size.
  • ::before = pseudo-element, :hover = pseudo-class.

JavaScript

  • Case-sensitive: addEventListener, getElementById.
  • Convert prompt() with Number().
  • Use === instead of ==.
  • Never name a function submit inside a form.
  • Script tag at the end of <body>.
  • Open the console (F12) — red text tells you the line and the error.

Workflow

  • Live Server extension = instant reload (you already know 👍).
  • One folder per project; keep images next to the HTML or use relative paths.
  • Delete commented-out dead code once it works.
  • Name files without typos — js3rdlectue.html vs js3rdlecture.js was a missing-file bug waiting to happen.
